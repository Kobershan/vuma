# Repository status — 2026-09-10

The following evidence was collected while completing the remaining stage audit:

- `dotnet build VumaRetail.sln --no-restore -c Release`: passed with zero errors.
- Architecture tests: 77/77 passed.
- Unit tests: 1,340/1,340 passed, including 9 Planning core and 15 conversation safety tests.
- Canonical integration suite: 552/552 passed against the disposable local PostgreSQL harness.
- Focused workflow integration: 11/11 passed.
- Stage 06d-focused unit tests: 129/129 passed; credit/availability integration: 5/5 passed.

The conversation entitlement manifest and valid three-part permission keys are registered. Sensitive
document delivery now requires a verification no older than 24 hours, as required by Stage 22b. A
signature-verified WhatsApp webhook adapter forwards only normalized messages into the existing inbound
path; its HMAC verifier has valid, tampered, and unsigned regression coverage.

The company EF model now includes the `conversations` schema with `conversations`, append-only
`conversation_turns`, and indexed `document_delivery_tokens` tables. Migration
`20260910161332_Stage22b_Conversations` was generated with a reversible `Down`, and
`dotnet ef migrations has-pending-model-changes` reports no pending model changes.
Production DI now uses a scoped EF-backed delivery-token store; the in-memory store remains only when
the application service is constructed without a persistence port (the unit-test fallback). The
anonymous one-time fetch repository is recorded as an edge-service transaction exception in the
pipeline architecture guard.

Contact bindings are now modeled in the tenant registry as `registry.contact_bindings`, with unique
channel/address and contact indexes. Migration `20260910162218_Stage22b_ContactBindings` is reversible,
and the registry EF model also reports no pending changes. The follow-up
`20260910164254_Stage22b_RegistryModelAlignment` migration persists the previously omitted
`verification_challenges` table. Production contact resolution uses this
tenant-scoped table; the in-memory resolver remains available for isolated tests.

Tenant-side binding management is now exposed under `/api/v1/contact-bindings`: list, create, issue
challenge, verify, grant/withdraw consent, and revoke. OTP challenges are persisted as hashes in `registry.verification_challenges`
and are tenant-filtered. The high-risk binding-management permission gates every management route.

Inbound messages now create or reuse durable company conversation state and append an inbound
`conversation_turns` row before classification. Withdrawn bindings are stopped immediately, before
transcript creation; sensitive delivery also requires explicit granted consent. The production store is scoped to the EF context;
anonymous onboarding still returns before any conversation or transcript row is created.

This is an evidence record, not a claim that the whole roadmap is complete. Stage 22b still needs
Stage 22 transport integration, persistence, real module-backed intent handlers, metering, and
dependency verification. Future roadmap stages also remain in the
task inventory and must not be marked complete without their implementation and exit evidence.
